# Правила разработки English Melody

## TDD
1. Написать тест, воспроизводящий дефект или требование.
2. Запустить тест и подтвердить ожидаемое падение.
3. Реализовать минимальное исправление.
4. Повторить все тесты, затем выполнить рефакторинг.
5. Не переходить к следующему функционалу до прохождения проверок текущего этапа.

## Запуск тестов
Node.js 22: `node --test scoring.test.mjs`.
Текущий результат локального тестирования модуля: RED 3/6, GREEN 6/6.
Интеграционные и браузерные проверки пока не выполнены.

## Стиль
Разделять HTML, CSS, данные и бизнес-логику. Использовать понятные английские имена, небольшие функции, комментарии о причинах решений. Не хранить секреты в репозитории. Новые зависимости проверять на лицензии и безопасность.

## Контент и приватность
До публикации каждого трека проверять разрешения на аудио, текст, перевод, упражнения и распространение. Фиксировать источник, автора, лицензию и атрибуцию. Бесплатный API сам по себе не даёт прав на контент. Не обходить ограничения источников. Загруженные пользователем файлы обрабатывать локально; не отправлять их третьим лицам без отдельного согласия. Не подключать аналитику без проверки требований приватности.

## Текущие ограничения
Прототип содержит оригинальные учебные тексты без записей. Код интерфейса ещё требует декомпозиции и браузерных тестов. Публикация GitHub Pages не подтверждена. Лицензия на исходный код проекта пока не выбрана владельцем.
